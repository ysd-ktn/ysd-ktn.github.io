コードが書けないデザイナーの
バイブコーディング実践記

PUBLISHED:2026.06.14 TAG:AI·DESIGN
01-CLAUDE.WEBP — 1600×900
INDEX OF THIS ARTICLE

「AIエージェント」「プロンプトエンジニアリング」「バイブコーディング」。SNSで目にする機会も多くなってきたこれらの言葉ですが、正直、作りたいものもない中でそれらを試す機会もなかなかなく、気にはなりつつも放置してきました。

そんな中、「Claudeがなんかマジですごいらしい」と人から勧められたのをきっかけに、重い腰を上げて触ってみることにしました。この記事は、コードがまったく書けないデザイナーが、3週間かけて自分のポートフォリオサイトを一から作り直した記録です。

きっかけは「なんかすごいらしい」

私はデザイナーです。Figma は毎日触るし、CSS もなんとなく読めます。でも「読める」と「書ける」の間には深い谷があって、その谷を埋めるために時間を使う気にはずっとなれませんでした。エンジニアに頼めば済む話だし、頼めない環境では諦めればいい。そう思っていました。

コードが書けないことをコンプレックスに思う必要はない。でも「書けないから選べない」状態は、デザイナーとしての選択肢を確実に狭めている。

この感覚が変わったのは、実際に手を動かし始めてからでした。

環境構築でいきなり詰まった

最初の壁は、想像通り環境構築でした。ターミナルという黒い画面に何を打てばいいのか分からない。npm と node の違いも分からない。ここで多くの人が脱落するんだろうな、と思いながら、分からないことをそのまま質問することにしました。

分からないことを、分からないまま聞く

結果的にこれが一番効きました。「エラーが出ました」ではなく、画面に出た文字をそのまま貼る。すると次にやることが1つだけ返ってくる。それを実行する。この繰り返しで、3日目にはローカルサーバーが立ち上がっていました。

$ npm install
$ npm run dev

  astro  v6.2.0 ready in 412 ms
  ┃ Local    http://localhost:4321/

この localhost:4321 が自分のブラウザに表示された瞬間のことは、たぶん結構長く覚えていると思います。

デザイナーの言語でAIに話しかける

ここからが本題です。私はコードの語彙を持っていませんが、デザインの語彙は持っています。そして分かったのは、デザインの語彙のままで十分に伝わるということでした。

  • 「カードの余白が詰まりすぎているので、上下を1.5倍にしたい」
  • 「ホバーしたときに、画像のグレースケールが解けて色が点く感じにしたい」
  • 「この行、日本語だと1行が長すぎて読みにくい。40字くらいで折り返して」

どれも「実装の指示」ではなく「意図の説明」です。意図さえ正確に言語化できれば、実装は向こうがやってくれる。つまりこの作業で問われていたのは、コードの知識ではなく自分が何を作りたいのかを言葉にする能力でした。それはデザイナーが普段からやっていることです。

できたもの、できなかったもの

3週間で、Astro 製のポートフォリオサイトが完成しました。カスタムカーソル、スクロール連動のナビ、コンテンツを JSON で管理する仕組みまで含めて、全部自分の手元にあります。

一方で、できなかったこともあります。設計の妥当性を自分で判断できない。「これで合ってますか」と聞くしかない場面が何度もありました。ここは今後の課題として残っています。

それでも、「作れないから諦める」が「作ってみてから考える」に変わったのは、私にとって決定的な変化でした。
